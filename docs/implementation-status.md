# حالة تنفيذ Classroom — checkpoint 1

## تم تنفيذه

تم إنشاء مشروع Supabase جديد مجاني في المنظمة الجديدة `ahmedeid2006's Org`، وتطبيق مخطط PostgreSQL فعلي يضم الملفات الشخصية، الفصول، العضويات، الدعوات، الواجبات، التسليمات، الدرجات، الاختبارات ونسخها، المحاولات، إعدادات AI، jobs، الإشعارات وسجل التدقيق.

تم تفعيل RLS على كل الجداول، مع دوال مملوكة/عضوية آمنة، RPC لإصدار الدعوات والانضمام إليها وفحص السعة، وRPC يعيد أسئلة الاختبار للطالب دون مفاتيح الإجابة. تم إغلاق تنفيذ دوال `SECURITY DEFINER` أمام `anon` و`PUBLIC`، وترك التنفيذ فقط لمسارات authenticated المطلوبة.

بعد مراجعة ACL، أضيفت migration hardening تمنح RLS predicates صلاحية التنفيذ اللازمة، تمنع ربط assignment/quiz بفصل يملكه مدرس آخر، تتحقق من أن الدعوة تُستخدم بواسطة طالب نشط، وتحجب عمليات الكتابة المباشرة لمحاولات الاختبار والدرجات والتسليمات والسجل حتى تُنقل إلى RPCs خادمية ذرية.

تم بناء واجهة عربية RTL متجاوبة للصفحة العامة وتسجيل الدخول والتسجيل والدعوات ولوحات المدرس والطالب والفصول وتفاصيل الفصل. صفحة الفصل تسمح بإصدار رابط دعوة حقيقي، والطالب لا يرى إلا الفصول والمواد والدرجات التي تسمح بها العضوية والنشر.

نجحت الاختبارات التالية: 5 assertions في Vitest، TypeScript، ESLint، وNext production build. تم فحص المعاينة في المتصفح، والتأكد من إعادة المسارات المحمية إلى `/login`.

## قيد معروف قبل التشغيل الفعلي

Supabase Phone provider ظاهر في لوحة المشروع على أنه Disabled. عند فتح إعداداته، طلبت اللوحة بيانات Twilio المطلوبة ولم تحفظ التفعيل بدونها. لذلك يجب إدخال بيانات SMS من مالك الحساب أو اختيار إعداد مصادقة مدعوم آخر قبل تسجيل مستخدمين حقيقيين بالهاتف. لا توجد بيانات اعتماد SMS محفوظة في المشروع.

## غير مكتمل بعد

رفع الملفات الخاص مع signed URLs، واجهة إنشاء وتحرير الواجب، محرر JSON للاختبارات، النسخ immutable، محاولات الاختبار والتصحيح الموضوعي، provisioning المدرسين، reset/MFA، jobs مزودات AI، تقارير CSV، واختبارات E2E/RLS بمستخدمين حقيقيين.
